# 案件・受注率管理ダッシュボード（客先提案用デモ版）

このリポジトリは、社内で実際に使っている案件管理ダッシュボードを、
**客先への提案・デモ用に複製したもの**です。会社名・案件・担当者名は
すべて架空のダミーデータです。

実際の社内版とは異なり、**Firebase（Firestore）には接続していません**。
データはブラウザのメモリ上にのみ保持されるため、ページを再読み込みすると
最初のダミーデータに戻ります（デモとして毎回同じ状態から見せられる、
という利点でもあります）。

## 主な機能

- 案件のステータス管理（進行中・受注・納品済み・ロスト）
- カテゴリー別・月別・年別の受注率分析
- 会社ごとの実績閲覧、訪問記録
- 参考見積り（社内検討中の案件）の管理
- **CSVファイルからの一括取り込み**（ステージ／新規・既存／初回入力日／
  優先度／受注予定日／クライアント名／案件名／進捗／売上見込額／
  営業担当の列を読み取り）
- スマホ対応レイアウト

## 1. セットアップ（あなたのPCで一度だけ）

Node.js（18以上推奨）がインストールされたPCで、このフォルダに移動して：

```bash
npm install
```

## 2. ローカルで動作確認する

```bash
npm run dev
```

表示された `http://localhost:5173/` をブラウザで開いて確認してください。

## 3. GitHubにアップロードして、URLで誰でも見れるようにする（GitHub Pages）

このプロジェクトには、GitHub Pagesへpushするたびに自動でビルド・公開される
GitHub Actionsの設定 (`.github/workflows/deploy.yml`) がすでに入っています。
Firebaseを使わないため、社内版のようなSecretsの登録は不要です。

### 手順

1. GitHubで新しい空のリポジトリを作成する（例: `sales-dashboard-demo`）
2. このフォルダのターミナルで、以下を実行してコミット・pushする

   ```bash
   git init
   git add -A
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```

   初回push時にGitHubのユーザー名とPersonal Access Token（repoとworkflowの
   権限にチェックを入れて発行したもの）の入力を求められます。

3. GitHubのリポジトリページで **Settings → Pages** を開き、
   「Build and deployment」の **Source** を **GitHub Actions** に設定する
   （最初の1回だけ）

4. 数分後に

   ```
   https://<あなたのユーザー名>.github.io/<リポジトリ名>/
   ```

   のURLで公開されます。このURLをそのまま客先に共有できます。

### 今後の更新について

```bash
git add -A
git commit -m "変更内容"
git push
```

するだけで自動的にサイトが更新されます。

## 4. 注意点

- データは各自のブラウザ上でのみ保持されます。相手に見せている間に
  こちらで登録した案件は、相手の画面には反映されません（別々の状態です）。
- ページを再読み込みすると、ダミーデータの初期状態に戻ります。
- CSV取り込み機能はローカルで完結しており、外部にデータは送信されません。
